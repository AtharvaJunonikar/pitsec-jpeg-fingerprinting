# PITSEC: JPEG Library Fingerprinting

A machine learning forensics project to identify which libjpeg version was used to compress a JPEG image based on re-compression artifacts and structural similarity measurements.

## Project Overview

This project implements a forensic fingerprinting system that classifies JPEG images by their compression library version. The approach is based on **Benes et al. (2022)** and uses re-compression artifact detection combined with machine learning.

### The Core Idea

When a JPEG compressed with library version A is re-compressed with the same version A, the rounding errors align, producing minimal distortion. When re-compressed with a different version B, systematic pixel-level disagreements appear across the image. These imperceptible-to-humans differences are measurable with **SSIM (Structural Similarity Index)** and form the basis for classification.

### What Gets Measured

For each image, the pipeline:
1. Re-compresses it with 4 benchmark versions (one per cluster)
2. Measures divergence using SSIM across RGB channels
3. Applies min-max normalisation
4. Produces an 8-feature vector for ML classification

## Key Concepts

### Four Libjpeg Version Clusters

The 24 libjpeg versions group into 4 clusters based on compression behaviour:

- **C0**: Legacy upsampling family (v6b, turbo120, ..., mozjpeg201)
- **C1**: DCT-scaling family (v7, v8, v8a, v9, v9a, v9b, v9c, v9d)
- **C2**: New chrominance quantization (v9e, v9f)
- **C3**: mozjpeg progressive family (mozjpeg300, mozjpeg403)

Benchmark sample points (one per cluster): `['6b', '7', '9e', 'mozjpeg300']`

### SSIM (Structural Similarity Index)

Measures image similarity on a scale of 0 (completely different) to 1 (identical) by comparing:
- **Luminance** (average brightness)
- **Contrast** (variance of brightness)
- **Structure** (correlation of pixel patterns)

Converted to % divergence: `divergence = (1 - SSIM) * 100`

### Double-Compression Matrix

For each image, a 4×4 matrix of divergence scores is computed:

```
           Decoder →
           6b    7    9e   mozjpeg300
Encoder ↓
6b       LOW  HIGH  HIGH   HIGH
7       HIGH  LOW   MED    HIGH
9e      HIGH  MED   LOW    HIGH
mozjpeg LOW  HIGH  HIGH    LOW
```

Low values on the diagonal (matching encoder/decoder) and high off-diagonal values distinguish which cluster an image belongs to. Min-max normalisation makes this pattern content-independent.

## Classifier Options

The project requires an explainable ML classifier (no deep learning):

1. **Decision Tree** (recommended) — Produces interpretable rules like "if norm_Cb < 0.2 AND diff_C1 > 3.1 → C2"
2. **Random Forest** — Higher accuracy; feature importance scores show which measurements matter most
3. Both implemented in `sklearn` (scikit-learn)

See Section 6 of `PITSEC_ProjectGuide.pdf` for code examples and evaluation strategies.
